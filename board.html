Task board

A Trello-style board for running the project. Each card is a work package from the WBS, tagged with the milestone it counts toward. Drag cards across the board as work moves; the milestones above fill in as their work packages reach Done.

Why both? The WBS says what must be delivered. The board shows the state of each piece right now. Milestones show whether we're on track. This board connects all three.

Tip: drag cards between columns, or use ◀ ▶ on a card. Click a card's title to edit it. Changes are saved in this browser.

How to run a project on this board

  1. Build the WBS first. Switch to the WBS tree and add every work package under its branch.
  2. Tag each card with a milestone. A milestone is reached only when all its cards are Done.
  3. Pull work from left to right. Backlog → To do → In progress → Review → Done.
  4. Respect the WIP limit. Only 3 cards in progress at once. Finish before you start.
  5. Use Review for acceptance. A card moves to Done only when the deliverable is checked.
  6. Report milestones, not cards. Sponsors want the strip at the top, not 18 cards.

WBS rules the board follows

  • 100% rule: the work packages add up to all the project's work, and nothing outside it. If it's not on the board, it's not in scope.
  • Work package = lowest WBS level, the size you can estimate, assign, and track. That's why each card has an owner and an estimate.
  • 8/80 rule (rule of thumb): a work package should take between 8 and 80 hours of effort.
  • WBS codes (2.1, 4.3…) are unique IDs that link each card to the WBS dictionary, schedule, and cost estimates.
  • Deliverables, not actions: name cards by the result ("Grades module"), not the verb.

📝 PMP exam tips

  • A task board or Kanban board is an information radiator: a visible display that shows progress without status meetings.
  • WIP limits expose bottlenecks and improve flow. If a column is always full, that's where the work is stuck.
  • The WBS is part of the scope baseline (scope statement + WBS + WBS dictionary). It is not a schedule; it has no dates or sequence.
  • Work packages are decomposed into activities later, in Define Activities, which is also where the milestone list is created.
  • In agile, the board is driven by the product backlog; "Done" must meet the team's Definition of Done.
