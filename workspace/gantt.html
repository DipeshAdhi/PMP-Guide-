Gantt chart

A Gantt chart is a bar chart of the schedule. Activities run down the left, time runs across the top, and each bar's length shows how long the activity takes. It's the most common way to show a project schedule because anyone can read it at a glance.

Also called: a bar chart, one of the formats of the project schedule produced by Develop Schedule. Named after Henry Gantt, who popularized it in the 1910s.

Try it: the Scholar Academy schedule

Use − and + to change any task's duration. Bars move to respect the dependencies, and the end date updates. Turn on the critical path to see which tasks control the end date, and float to see how much each other task can slip.

How to read a Gantt chart

  • Each row is an activity, usually from the WBS.
  • Bar start and end show the planned start and finish dates.
  • Bar length shows the duration.
  • Arrows show dependencies: which task must finish before another can start.
  • Diamonds are milestones (zero duration).
  • Overlapping bars are tasks that run in parallel. Check that they don't need the same person.
  • A "today" line and percent-complete shading are often added for tracking.

Strengths and limits

Good for:

  • Communicating the schedule to the team and stakeholders
  • Seeing parallel work and resource clashes
  • Tracking progress against the baseline

Not good for:

  • Showing complex logic. A network diagram is clearer for that.
  • Showing float and the critical path, unless the tool computes them (as here)
  • Executive reporting. Use a milestone chart instead.

The four dependency types

Every arrow in a schedule is one of these. Finish-to-Start is by far the most common, and it's the only type used in the chart above.

Leads and lags

Lag = a forced wait after the predecessor. "Paint, then wait 2 days for it to dry before carpeting" → FS + 2.

Lead = the successor starts early, overlapping the predecessor. "Start testing 3 days before coding finishes" → FS − 3.

Why dependencies exist

  • Mandatory (hard logic): physically required. You can't test code that isn't written.
  • Discretionary (soft logic): best practice the team chooses.
  • External: depends on something outside the project, like a vendor delivery.
  • Internal: between activities inside the project.

📝 Key points to remember

  • Bar charts, milestone charts, and network diagrams are all presentations of the project schedule (output of Develop Schedule).
  • FS is the most common dependency type; SF is the rarest.
  • A lag adds waiting time; a lead lets work overlap. Using leads is a form of fast tracking.
  • To report the schedule to executives, use a milestone chart, not the detailed Gantt.
  • Dependencies are documented in Sequence Activities, before any Gantt chart is drawn.
